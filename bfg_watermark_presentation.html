bfg_watermark
Documentació Completa

La llibreria Python que gestiona la càrrega incremental de dades a Microsoft Fabric. Controla automàticament quin rang de dates extreure, detecta errors, i actualitza l'estat de cada taula en un sol MERGE atòmic.

📋 Taula: Watermark_Control
📚 Lakehouse: LH_BRONCE_PLATA
🔓 Versió: 1.0.4
🚀 4 mòduls: Query · Config · Session · Admin

Concepte: Què és un Watermark?

La idea clau Cada nit guardem la data de l'últim registre processat. La nit següent, només demanem els registres més nous que aquella data.

📈 Primera vegada (FULL_RELOAD)

Descarrega tota la taula de l'origen. La Watermark_Control ho detecta automàticament quan WATERMARK_LAST_VALUE és NULL.

⚡ Nits següents (INCREMENTAL)

Descarrega només els registres nous o modificats des del darrer watermark, menys la finestra de seguretat (WINDOW_DAYS) per evitar buits.

🧠 La WT és el cervell

Ens ajuda a centralitzar les càrregues de les taules en el sistema i gestionar-les fàcilment. Tots els paràmetres viuen a la Watermark_Control. A més a més, és molt útil ja que ens permet automatitzar el Data Quality. Els Notebooks no contenen hardcoded logic: simplement pregunten "com t'he de tractar?" i actuen.

La Taula Watermark_Control

20 columnes organitzades en 5 grups funcionals. Clau primària: SOURCE + TABLE_NAME.

Columna Tipus Exemple Descripció
👤 A — IDENTITAT
SOURCE STRING 'SAGE' Identificador del sistema d'origen (ex: 'SAGE', 'ORACLE', 'MSSQL'). Agrupa totes les taules d'un mateix sistema i és el filtre principal als Pipelines i a WatermarkQuery.source(...).
TABLE_NAME STRING 'PORDER' Nom exacte de la taula a l'origen. No és el nom a Plata, sinó el nom de l'objecte a la base de dades font. Juntament amb SOURCE forma la clau primària de la WT.
AREA STRING 'COMPRES' Àrea de negoci (ex: 'COMPRES', 'VENDES', 'STOCKS'). Permet activar/desactivar o saltar grups sencers de taules amb una sola instrucció d'Admin.
IS_DIMENSION BOOLEAN false Indica si és una dimensió (true) o una taula de fets (false). Les dimensions acostumen a carregar-se senceres cada vegada (FULL_RELOAD).
🔎 B — ENRUTAMENT
SILVER_TABLE STRING 'silver_sage_compres_porder' Nom complet de la taula Delta destí a la capa Plata. El Notebook hi escriu el resultat final. S'usa amb DeltaTable.forName(spark, cfg.silver_table) o saveAsTable().
BRONZE_PATH STRING 'file:/lakehouse/default/Files/Bronze/Sage/Compras/PORDER.parquet' Ruta relativa on el Pipeline guarda el .parquet. El Notebook Bronze→Plata llegeix exactament d'aquí. Ha de coincidir amb la ruta configurada al Copy Data.
🔨 C — EXTRACCIÓ I MERGE
SOURCE_QUERY STRING 'SELECT ... FROM porder' Query SQL completa sense filtre de dates. cfg.build_source_query() hi afegeix automàticament el filtre WHERE <datecol> >= '<from_date>' i una clàusula EXISTS de control si el mode és incremental. Això evita extreure dades innecessàriament. NULL = el notebook gestiona la query manualment.
SOURCE_DATECOL STRING 'UPDDATTIM_0' Columna de data/timestamp a l'origen usada per al filtre incremental. Ha d'actualitzar-se sempre que el registre canvia (típicament la columna d'última modificació del sistema origen).
SOURCE_DATECOL_FORMAT STRING '%Y-%m-%d %H:%M:%S' Format Python (strftime) per representar la data del filtre al SQL. Per defecte '%Y-%m-%d %H:%M:%S'. Ajustar si la font espera un format diferent (ex: Sage amb TO_TIMESTAMP de Oracle).
WINDOW_DAYS INTEGER 2 Dies de solapament aplicats al watermark per seguretat. Si el watermark és 15 gen i WINDOW_DAYS=2, el filtre busca a partir del 13 gen. Evita buits per problemes de rellotge. 0 = sense solapament.
PK_COLUMNS STRING (JSON) '["NUM_0","CPY_0"]' Array JSON amb les columnes que formen la clau primària a l'origen. El Notebook usa cfg.pk_columns per construir la condició del MERGE. Ha d'estar en format JSON vàlid amb cometes dobles.
⚙️ D — CONTROL D'EXECUCIÓ
ACTIVE BOOLEAN true Activa o desactiva la taula del cicle de càrrega. false = ignorada per .active_only() i .runnable(). Per apagar taules permanentment sense esborrar-les de la WT.
LOAD_MODE STRING 'INCREMENTAL' Mode permanent per defecte. INCREMENTAL = només novetats; FULL_RELOAD = tot cada cop (dimensions); SKIP = mai executar (desactivació funcional).
NEXT_RUN_MODE STRING / NULL 'FULL_RELOAD' Override puntual per a la propera execució. Sobreescriu LOAD_MODE una sola vegada. La sessió el posa a NULL automàticament si l'execució acaba bé. Usat per admin.force_full_reload() i admin.skip_next_run().
RUN_ORDER INTEGER 1 Prioritat d'execució dins del Pipeline. Les taules amb RUN_ORDER menor s'executen primer quan s'usa .ordered(). Útil per garantir que les dimensions s'executen abans que els fets.
📊 E — ESTAT I AUDITORIA (escrites automàticament per la llibreria)
WATERMARK_LAST_VALUE TIMESTAMP 2025-01-16 08:15:00 Data/hora del registre més recent processat en l'última execució exitosa. El proper cicle incremental filtra per registres posteriors a aquest valor (menys WINDOW_DAYS). Si és NULL → el sistema forçarà un FULL_RELOAD automàticament.
LAST_RUN_AT TIMESTAMP 2025-01-16 08:17:42 Data i hora exacta en que va acabar l'última execució (exitosa o fallida). Útil per detectar taules desactualitzades amb admin.stale().
LAST_RUN_OK BOOLEAN true true si l'última execució va finalitzar sense errors, false si va fallar. Combinada amb LAST_ERROR permet veure l'estat de salut del sistema d'un cop d'ull.
LAST_ERROR STRING NULL Missatge d'error (màxim 500 caràcters) de l'última execució fallida. NULL quan LAST_RUN_OK = true. La sessió el neteja automàticament en la propera execució exitosa.
CREATED_AT TIMESTAMP 2024-11-01 09:00:00 Data/hora de creació de la fila. S'estableix una sola vegada durant la inserció via NB_Init_Watermark_Table.
UPDATED_AT TIMESTAMP 2025-01-16 08:17:42 Data/hora de l'última modificació, ja sigui per una execució del Pipeline o per una operació manual via WatermarkAdmin. Permet auditar canvis.

▶ Lògica de prioritat del mode efectiu

1

Si NEXT_RUN_MODE té valor S'aplica el valor de NEXT_RUN_MODE (override puntual). Netejat automàticament per la sessió si l'execució acaba bé.

2

Si WATERMARK_LAST_VALUE és NULL S'aplica FULL_RELOAD automàticament, independentment del LOAD_MODE. Primera càrrega ever.

3

En cas contrari S'aplica el LOAD_MODE permanent de la taula.

Arquitectura del Sistema

Dos nivells de Pipelines i un sistema de Notebooks, tots coordinats per la Watermark_Control.

⏰
Horari programat

Activa el Pipeline Mestre (PL_Programador_WT_<Origen>) de forma automatitzada.

1
Notebook de Queries (NB_Querys_<Origen>)

Llegeix la Watermark_Control amb WatermarkQuery. Per cada taula executable, crida cfg.build_source_query() que retorna el SQL complet (amb filtre de dates ja inclòs si és incremental). Genera un JSON i el retorna al Pipeline.

2
Pipeline d'Extracció — ForEach + Copy Data (PL_<Origen>_WT)

Itera el JSON. Per a cada taula, una activitat Copy Data executa el SQL directament contra l'origen (via ODBC/Linked Service) i guarda el resultat com a .parquet a la ruta BRONZE_PATH del Lakehouse. El Copy Data no sap si és incremental: tota la intel·ligència és al SQL del pas anterior.

3
Notebook de Transformació (NB_Bronce_a_Plata_<Origen>)

Quan l'extracció acaba, el Pipeline Mestre activa aquest Notebook. Per a cada taula: obre una watermark_session, llegeix el .parquet de Bronze, aplica el FULL_RELOAD o el MERGE incremental a la taula Delta de Plata, calcula el màxim de la columna de data i crida cfg.set_new_watermark(max_date). En sortir del with, la sessió actualitza la WT en un sol MERGE atòmic.

✓ Un sol MERGE al final La sessió agrupa tota l'actualització de la WT en un sol MERGE Delta atòmic. No hi ha escriptures parcials.
⚠ Lakehouse per defecte Qualsevol Notebook que usi bfg_watermark ha de tenir LH_BRONCE_PLATA com a Lakehouse per defecte, o cridar spark.catalog.setCurrentDatabase("LH_BRONCE_PLATA").
🔒 Transaccionalitat garantida Si el codi falla, el watermark NO avança. L'error queda guardat a LAST_ERROR i la propera execució pot reintentar des del mateix punt.

Guia d'Operacions del Dia a Dia

Com gestionar el sistema en les situacions habituals.

📄 Afegir una taula nova

  1. Obre el notebook NB_Init_Watermark_Table. Localitza el bloc de l'origen corresponent.
  2. Afegeix el nom de la taula i les seves claus primàries a la llista de tuples.
  3. Afegeix la query SQL al diccionari de queries.
  4. Executa el notebook sencer. Fa un MERGE: insereix la taula si no existeix, o actualitza la query si ja hi era.
  5. Si la taula és petita: no cal fer res més. El proper cicle del Pipeline la trobarà amb WATERMARK_LAST_VALUE = NULL, farà un FULL_RELOAD automàtic i guardarà el watermark.
  6. Si la taula és gran (historial massiu): consulta la secció d'Escenaris Especials.

🔄 Forçar la recàrrega completa d'una taula

  • Quan usar-ho: has canviat l'esquema de la taula Silver, o sospites inconsistències entre Bronze i Plata.
  • Des d'un notebook interactiu: admin.force_full_reload(source="SAGE", table="PORDER")
  • Posa NEXT_RUN_MODE = 'FULL_RELOAD'. La propera execució del Pipeline carregarà tota la taula des de zero i netejarà l'override automàticament.

⚠️ Bloquejar temporalment una taula problemàtica

  • Cas d'ús: l'origen d'una taula concreta té problemes i vols que el Pipeline continuï amb la resta.
  • Marcar com a SKIP: admin.skip_next_run(source="SAGE", table="SINVOICE")
  • Tornar a activar quan l'origen estigui reparat: admin.resume_from_skip(source="SAGE", table="SINVOICE")
  • Per desactivar tota una àrea indefinidament: admin.deactivate(source="SAGE", area="COMPRES")

🔨 Modificar i empaquetar la llibreria

  1. Modifica el codi Python de bfg_watermark localment.
  2. Executa al terminal: python setup.py bdist_wheel. Es crea el fitxer .whl a la carpeta dist/.
  3. A Fabric: ves a Environments → obre el teu DEFAULT_ENV.
  4. Ves a la pestanya Custom Libraries, puja el nou .whl substituint l'anterior, i fes Publish. Tots els Notebooks prendran la nova versió.

Escenaris Especials

Com actuar en situacions fora del flux habitual.

📦 A. Càrrega inicial massiva (historial gran)

Una taula nova té 30+ milions de registres. Executar el Pipeline sencer faria que el Copy Data consumís masses CUs i potser fallés per timeout.

  1. Extracció manual: des del teu ordinador (DBeaver, SSMS, etc.), exporta totes les dades a un fitxer .parquet.
  2. Puja a Bronze: ves a l'explorador de fitxers de MS Fabric i puja el .parquet exactament a la ruta BRONZE_PATH que figura a la WT per aquesta taula.
  3. Verifica el mode: assegura't que NEXT_RUN_MODE = 'FULL_RELOAD' o que WATERMARK_LAST_VALUE sigui NULL: admin.force_full_reload(source="SAGE", table="PORDER")
  4. Executa NOMÉS el Notebook de transformació: ves al notebook NB_Bronce_a_Plata_<Origen> i executa'l de forma aïllada des de MS Fabric (no el Pipeline sencer). El Notebook detectarà el FULL_RELOAD, llegirà el teu enorme .parquet i l'introduirà a Plata. En acabar bé, la sessió netejarà l'override i avançarà el watermark. La propera nit, el Pipeline correrà en mode INCREMENTAL amb normalitat.

⏩️ B. Executar només algunes taules (SKIP selectiu)

Per incidència puntual, vols executar el Pipeline però ometre taules concretes.

  • Marcar les taules a saltar: admin.skip_next_run(source="SAGE", table="SINVOICE")
  • Executa el Pipeline normalment: processarà totes les taules EXCEPTE les marcades.
  • L'endemà, les taules tornaran al mode INCREMENTAL automàticament.

⏪️ C. Recuperar la WT d'un estat corromput (Delta Time Travel)

Algú ha modificat la Watermark_Control per error.

  • Veure l'historial de versions: display(admin.show_history())
  • Inspeccionar l'estat en la versió 5 sense modificar-la: display(admin.inspect_table(version=5))
  • Si sembla correcta, restaurar-la (acció destructiva): admin.recover_table(version=5)
  • O per timestamp: admin.recover_table(timestamp="2025-01-15 08:00:00")
🔒 Recordatori: Lakehouse per defecte Qualsevol Notebook que usi bfg_watermark ha de tenir LH_BRONCE_PLATA com a Lakehouse per defecte. Si el teu Notebook necessita un altre Lakehouse, afegeix al principi: spark.catalog.setCurrentDatabase("LH_BRONCE_PLATA")

Referència de l'API

import bfg_watermark as wm — 4 components principals.

A. WatermarkQuery — Consulta Fluent

Builder fluent per consultar la Watermark_Control. S'encadenen filtres i es finalitza amb .build() o .one().

Mètode Exemple Descripció
Filtres (encadenables)
.source(*sources) .source("SAGE") Filtra per sistema d'origen. Múltiples valors fan OR.
.area(*areas) .area("COMPRES") Filtra per àrea de negoci. Múltiples valors fan OR.
.table(*tables) .table("PORDER","SORDER") Filtra per nom de taula. Múltiples valors fan OR.
.dimension(bool) .dimension(True) Filtra per el flag IS_DIMENSION.
.active_only() .active_only() Exclou files amb ACTIVE = false.
.runnable() .runnable() Recomanat per Pipelines. Aplica active_only() i exclou taules on effective_mode = SKIP.
.mode(*modes) .mode("INCREMENTAL") Filtra pel LOAD_MODE permanent.
.ordered() .ordered() Ordena per SOURCE, RUN_ORDER, TABLE_NAME.
Terminals (executen la consulta)
.build() → list[WatermarkConfig] Executa i retorna una llista. Pot ser buida.
.one() → WatermarkConfig Executa i retorna exactament un resultat. Llança ValueError si n'hi ha 0 o més d'1.

B. WatermarkConfig — Configuració d'una Taula

Encapsula una fila de la WT i calcula automàticament l'estratègia. S'obté via WatermarkQuery, mai s'instancia directament.

Propietat / Mètode Tipus Descripció

.build_source_query() str|None Retorna el SQL complet amb el filtre de dates i una clàusula EXISTS ja afegits si és incremental, permetent a la base de dades retornar 0 registres instantàniament si no hi ha novetats. None si SOURCE_QUERY no està configurat a la WT.
.set_new_watermark(val) — Sobreescriu el valor que es guardarà com a nou watermark quan la sessió finalitzi. Si no es crida, la sessió guarda datetime.now() per defecte.

C. watermark_session — Context Manager Transaccional

La peça clau del sistema. Gestiona el cicle complet i actualitza la WT en un sol MERGE atòmic al final.

✓️

Èxit

Avança WATERMARK_LAST_VALUE, posa LAST_RUN_OK = true, neteja LAST_ERROR, neteja NEXT_RUN_MODE si era un override.

❌

Error

Manté WATERMARK_LAST_VALUE intacte (no avança), posa LAST_RUN_OK = false, guarda el missatge d'error a LAST_ERROR. Relança l'excepció.

⏩️

Mode SKIP

Fa un yield del cfg i surt immediatament sense escriure res a la WT.

D. WatermarkAdmin — Operacions d'Administració

Modifica l'estat de la WT des de notebooks interactius. Tots els mètodes accepten filtres per source, area i/o table. Posa UPDATED_AT automàticament.

Mètode Descripció
Activació / Desactivació
admin.activate(source=,area=,table=) Posa ACTIVE = true per les taules que coincideixin.
admin.deactivate(source=,area=,table=) Posa ACTIVE = false. Les taules desactivades s'ignoren en .runnable().
Mode permanent
admin.set_mode(mode, source=,...) Canvia el LOAD_MODE permanent. mode ha de ser 'INCREMENTAL', 'FULL_RELOAD' o 'SKIP'.
Overrides puntuals
admin.force_full_reload(...) Posa NEXT_RUN_MODE = 'FULL_RELOAD'. Netejat automàticament per la sessió després de l'execució exitosa.
admin.skip_next_run(...) Posa NEXT_RUN_MODE = 'SKIP'. La propera execució s'obviarà completament.
admin.resume_from_skip(...) Neteja NEXT_RUN_MODE = 'SKIP' i/o LOAD_MODE = 'SKIP', tornant la taula a INCREMENTAL.
admin.reset_watermark(...) Posa WATERMARK_LAST_VALUE = NULL. La propera execució forçarà un FULL_RELOAD automàtic.
Diagnòstic
admin.status() DataFrame complet: mode, estat, watermark, última execució. Vista global del sistema.
admin.errors() Taules actives amb LAST_RUN_OK = false. Primera opció davant d'un error.
admin.stale(hours=25) Taules sense execució exitosa en les últimes hours hores. Detecta taules estancades.
Delta Time Travel
admin.show_history(limit=20) Historial de versions Delta de Watermark_Control. Per identificar quan estava en bon estat.
admin.inspect_table(version=,timestamp=) Llegeix la WT tal com era en una versió/timestamp concret, sense modificar-la.
admin.recover_table(version=,timestamp=) Acció destructiva: restaura la WT sencera a un estat anterior. Usar amb precaució.

Patrons de Codi

Exemples complets i comentats per als casos d'ús habituals.

Patró complet: Notebook Bronze → Plata

import bfg_watermark as wm
from delta.tables import DeltaTable
from pyspark.sql.functions import max as _max

def processar_taula(cfg: wm.WatermarkConfig):
    """Processa una sola taula: Bronze → Plata amb gestió de watermark."""
    with wm.watermark_session(spark, config=cfg) as cfg:
        # Llegir de Bronze
        df_bronze = spark.read.format("parquet").load(cfg.bronze_path)

        if cfg.effective_mode == wm.MODE_FULL_RELOAD:
            # Sobreescriure tota la taula de Plata
            (df_bronze.write
                .format("delta")
                .mode("overwrite")
                .option("overwriteSchema", "true")
                .saveAsTable(cfg.silver_table))

        elif cfg.effective_mode == wm.MODE_INCREMENTAL:
            # MERGE incremental contra la taula Delta de Plata
            delta_table = DeltaTable.forName(spark, cfg.silver_table)
            merge_cond = " AND ".join([f"target.{k} = source.{k}" for k in cfg.pk_columns])

            (delta_table.alias("target")
                .merge(df_bronze.alias("source"), merge_cond)
                .whenMatchedUpdateAll()
                .whenNotMatchedInsertAll()
                .execute())

        # Avançar el watermark al valor màxim trobat a Bronze
        if cfg.source_datecol:
            max_date = df_bronze.agg(_max(cfg.source_datecol)).collect()[0][0]
            if max_date:
                cfg.set_new_watermark(max_date)


# Obtenir totes les taules de SAGE executables i processar-les
configs = wm.WatermarkQuery(spark).source("SAGE").runnable().ordered().build()
for cfg in configs:
    processar_taula(cfg)

import bfg_watermark as wm
